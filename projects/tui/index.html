Normalizing hotel room descriptions

Turning inconsistent supplier language into explainable room-type matches.

The question

How can a system map free-text room descriptions to a standard catalog while recognizing when there is not enough information?

Approach

The team is separating catalog meaning from historical mapping behavior. Exploratory analysis examines missing descriptions, class coverage, conflicting labels, and differences between mapped history and the unmapped backlog. Identical descriptions are grouped when preparing evaluation splits so repeated wording does not make validation artificially easy.

My contribution

Contributed exploratory analysis and the ML framing of the mapping problem. I examined where historical labels are unreliable and how incomplete descriptions should affect matching. This informs a comparison of catalog-based and historical-example retrieval, with explanations and an explicit option to leave a description unmapped.

Results & evidence

Completed work includes data-quality analysis, a description-level evaluation design, and a defined mapping scope. The next modeling step is to compare multilingual embeddings and retrieval paths; production matching accuracy is not yet established.

Scope & interpretation

The capstone is in progress; a live production system is outside the agreed scope. The examples on this page are invented and do not reproduce client records or catalog codes.

What this work taught me

Knowing when a description cannot support a match is part of the classification problem.
